# MauForma v6.21 · 跨产品分阶段精修演练（完全虚构）

> 本页是**独立原创的纯文本示例**，不包含任何用户上传图片、企业名称、页面截图、业务数值、原样布局或外部 Skill 指令。展示“同样要去除不合理装饰，但不同产品不能修成同一种后台”的设计方法。

## 场景 A：社区设备维护控制台 — Operations × Operate

**用户工作**：工作人员查看维修告警、处理任务、确认处理结果。

| 阶段 | 模拟问题和修改判断 | 必须保护 |
| --- | --- | --- |
| R0 诊断 | 面板、告警和图表密密麻麻，按钮颜色/图标混乱；标出真正未处理的告警 | 任务权限、告警语义、真实时间 |
| R1 结构 | 让待处理任务和告警列表成为第一决策焦点，图表和汇总作为辅助；不能只留欢迎语 + 4 KPI | 待处理路径、筛选/处理操作 |
| R2 空间 | 采用共同 Grid 行线、父容器间距和可读表格；意图关联的表头/表体可共边 | 大量数据可扫描；不机械铺开巨型留白 |
| R3 配色图标 | 移除无意义的 emoji 装饰，将紧急/异常/成功分别归入语义色；使用一致图标家族 | 实际严重性和状态不能因为“好看”变成同一种灰色 |
| R4 圆角/组件 | 按控件/面板层级收敛圆角，统一操作按钮及输入尺寸 | 读屏、键盘、危险操作确认 |
| R5 复验 | 同一队列状态/分辨率比较，验证告警能否找到、任务能否执行、表格是否可滚到底 | 保留 P0 核心操作及证据 |

**反例**：把热闹橙色主题改成灰白、去掉所有 emoji、统一圆角，但用户仍找不到待处理任务——应返回 R1。

## 场景 B：个人植物观察课程 — Learning × Experience/Operate

**用户工作**：回访者选择下一节观察练习，完成记录，知道是否保存。

| 阶段 | 模拟问题和修改判断 | 必须保护 |
| --- | --- | --- |
| R0 诊断 | 首页只有“课程总数/累计时长/完成率”三张数据卡，没有下一练习入口 | 已完成课节、可靠保存状态 |
| R1 结构 | 采用“下一节任务优先”或“学习路径优先”两套不同信息组织，用户评审后确定 | 下一行动、练习阶段、继续/退出恢复 |
| R2 空间 | 课节/内容预览与主练习有合理留白；小屏将必要操作放在可触达位置 | 真实练习内容，不为了填空虚构奖励 |
| R3 配色图标 | 统一课程图标与提示色；可保留经过品牌批准的可爱植物插画/表情作为教学内容 | 活泼表达不能遮挡核心按钮或降低可读性 |
| R4 圆角/组件 | 用统一主题变体处理题卡、进度和反馈，避免每张卡片过度圆润 | 输入、音频和状态交互 |
| R5 复验 | 验证新用户与回访用户能否找到下一步；查看保存中/失败和窄屏状态 | 不宣称实际用户完成率已提高，除非有研究数据 |

**反例**：把首页设计成黑白管理后台，再把植物图标和“课程”字样加回去，仍没有真正的练习路径——不算通过。

## 场景 C：已批准页面上的局部修复 — Consumer Utility × Operate

用户只要求“设置里一个按钮错位”。保留原页面导航、品牌色和信息架构，检查按钮尺寸、相邻间距及窄屏回归即可；可标记 R1 为“不适用，布局已有批准”，但不得记成“R1 已完成全新 UX 研究”。

## 如何记录审查

每轮写下：产品类型、当前用户目标、需要保留的组件/数据、真实证据、主问题、改动范围、阶段 R0–R5 结果、宽屏和窄屏验证、尚未验证的部分。发现业务任务错配时优先返工 R1；UI 精修不能替代 UX 设计。
