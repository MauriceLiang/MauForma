# RepoVantage 发布页截图：纵向错列与底部空间（2026-11-04）

截图来源：用户提供的版本发布完整视图与局部放大图。以下仅解释**可见布局**，不能据此断言真实网页已经发生不可滚动裁切。真实源码、滚动容器和 CSS 状态未知。

## 截图证据

1. 「版本发布时间线」位于左上，「间隔顺序」位于右上。
2. 「相邻发布间隔」位于左下，「正式发布记录」位于右下。
3. 两列像分别纵向堆叠：右下卡片比左下更早开始；上排右卡较矮，造成第二行卡片顶边不一致。
4. 用户补充截图里，底部的发布记录列表接近视口/窗口边缘，缺少明确的收尾空间。这可能只是截图恰好裁到当前滚动位置，也可能是 fixed/container 高度问题，必须**滚动到终点**才能判断。
5. 标题、Release 标签、数据轴/单位等应保持可读；不要把这类数据内容强行缩小或删掉以塞进一个视口。

## 设计建议优先级

- **P0 网格结构**：改为共享行线的 `grid-template-areas` 或主时间线跨全行，避免 `left-column: [top,bottom]` 和 `right-column: [top,bottom]` 各自独立垂直布局。对齐目的不是全部等高，而是提供可识别的行起点与阅读顺序。
- **P1 信息必要性**：核查「间隔顺序」与「相邻发布间隔」是否同时必要；如重复，只保留最有用的一张，其余转详情或可展开内容。不能仅凭截图认为它们必然重复。
- **P2 内容末端**：全页或主内容区应自然滚动，最后一张记录的底边/最后一个箭头在最大滚动位置可见，且与视口底部有合理间距。若有固定底栏，要预留其真实高度。
- **P3 窄屏**：顺序切成单列，保持「时间线 → 间隔/分布 → Release 明细」的任务顺序，而不是让 DOM 顺序与视觉列顺序互相矛盾。
- **P4 浏览器证据**：使用实际视口截图 + scroll-to-end + 200% 文本放大；如果未运行，记录 `NOT RUN`。

## 不应追求的伪解决

- 把所有图表和列表压到窗口首屏；数据页允许合理纵向滚动。
- 通过 `overflow:hidden` 藏掉超出的部分。
- 加空白占位强迫左右图表底部完全等高。
- 只在大屏成功，笔记本矮窗口或 Safari 底部遮挡仍然存在。
