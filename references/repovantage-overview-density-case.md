# RepoVantage Overview 截图案例 · 信息过量但功能并不多（v6.8）

> 来源仅是用户提供的 **2026-11-03 总览截图**。下表为可见截图的视觉/内容审核与 MauForma 推荐策略；未读取 RepoVantage 业务仓库，不能假设按钮真正接通、导航路由已实现或演示数据真实。

## 截图中实际可见的内容

1. 左侧导航：总览 / 仓库（数字 7）/ 项目比较 / 研究分析 / 任务中心（数字 3）/ 设置。导航已有大部分分析入口。
2. 顶部：RepoVantage / 总览 面包屑与演示数据状态。
3. 页面标题：`总览` + `选择仓库、启动采集，再按说明查看开发活动、协作和版本发布。`。
4. **“从一个仓库开始”**：说明、当前示例仓库、选择仓库、开始采集、查看示例分析，多个动作同一区域。
5. **“使用说明”**：三个独立的编号操作卡（选仓库、采集并查看进度、阅读分析结果），底部各有跳转入口。
6. **“分析内容”**：开发活动 / Issue 与 PR / 版本发布，重复说明功能与访问路径，侧栏已有入口。
7. 底部：Mock 数据说明，Footer 又写 `交互原型 · Mock 数据` 及 `返回总览`。

这些信息单独看并非都错，但**同时展示造成“每个容器都像重要内容”**，需要做筛选与状态化呈现。

## 逐块信息处置建议

| 区域 | 保留/移入/按条件展示 | 原因 |
| --- | --- | --- |
| `总览` H1 | **keep / primary** | 明确当前页面 |
| 说明文案（选择仓库→采集→分析） | **merge / supporting**，必要时一句话 | 页面不需要再讲完整教程 |
| `从一个仓库开始` 主面板 | **replace** 为简洁当前仓库/主操作区 | 有业务价值的是用户下一步，不是再包装一层标题 |
| `选择仓库` / `开始采集` / `查看示例分析` | **按用户状态只突出一个主操作**；另两项次要按钮/链接 | 防止同时三 CTA 抢主角；有库/无库/是否采集决定优先操作 |
| 三张 `使用说明` 卡 | **conditional** 初次进入或求助时显示一项当前步骤，其他进入帮助 | 回访用户无需每次看到重复教程 |
| `分析内容` 三卡 | **deferred** 到既有导航或具体分析页面 | 功能入口已有，无法证明三卡能节省操作 |
| `演示数据` / `Mock 数据说明` | **保留清楚的来源提醒**，就近放在有影响的示例操作/数据附近 | 不能因为留白删除数据真实性提示；不要在每个区与 Footer 重复 |
| Footer `返回总览`（当前就在总览） | **remove**；如果用户确实需要返回其它来源另当别论 | 自链接没有新任务意义 |

## 推荐的页面状态，不强制一种通用截图

**首访且无仓库**：`总览` + 选择/添加仓库这一步 + 简短 Mock 状态 + 帮助链接。没有必要同时展现步骤 2、3 的大卡片。

**已有仓库、尚未采集**：当前仓库 + `开始采集` 是主操作；切换仓库为次级，演示浏览可以是额外入口（若功能真实存在）。

**回访且已有数据**：当前仓库 + 继续分析/上次任务/数据状态。不要仍显示 `从一个仓库开始` 和长教程。根据产品真实功能决定是否显示关键指标小摘要；不能虚构统计数据。

**数据分析详情**：信息密度可以明显更高，图表 + 指标 + 时间范围 + 来源说明是主内容，不按总览页规则删光。

**失败/权限错误**：需明确错误原因与重试/授权路径，即使这会占用更多空间。

## 审美目标

- 从**“大卡+三卡+三卡+脚注”**转为 **“少而清晰的主任务区 + 有必要时的一条补充路径”**。
- 先缩减重复容器数量，再合理使用 macro / meso / micro 留白；不可用强行拉高卡片或增加空白占位冒充高级感。
- 关键标签不要弱化成低对比小字；CTA 主次要明确，状态色与品牌色沿用用户已确认 Token。
- 用户已确认的导航位置和配色不能因为优化留白而被 AI 擅自改变。
