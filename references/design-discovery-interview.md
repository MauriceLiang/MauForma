# MauForma · 设计前访谈与视觉决策规范（v5.2）

## 目标与适用范围

在新网站、新产品、整体视觉改造或信息架构重大变更之前，先理解页面内容与用户目标，再与用户敲定视觉方向。此规则适用于 Vue、React、Nuxt、Next.js 等 Web 前端项目，**不限于后台管理系统**。

已有明确设计标准、仅修复局部组件、或用户已授权 AI 自主决定的任务，应避免机械重复提问。

## 阶段 1：检查项目

先读取现有页面、组件库、Design Tokens、产品定位、用户群体、主要任务和内容素材。不要在不了解业务时直接询问“你喜欢什么颜色”。对已确定的选择不要再提问。

## 阶段 2：向用户提供有区别的可选设计方向

优先确认三个核心属性（可合并为一轮简短问答）：

1. **视觉风格**：极简克制、编辑式高级感、温暖亲和、科技未来、专业高效，或用户自定义参考。
2. **信息密度**：低密度（强调图片与留白）、中密度（平衡）、高密度（任务效率）、混合密度（分页面自适应）。
3. **第一视觉焦点**：产品/食物图片、品牌主张、关键数据、核心操作，或其他内容。

仅在会改变实施方案时继续确认：主题颜色、浅色/深色、动效强度、素材策略、响应式重点、已有设计或品牌限制。

每个选项都解释具体视觉效果和权衡，不应只列模糊形容词。

## 阶段 3：提交设计简报

将结果记录为项目级设计简报。每项决策必须标注来源：

- confirmed：用户明确确认
- delegated：用户授权由 AI 决定
- inherited：沿用既有设计体系
- unresolved：尚未确定，不能伪称确认

至少记录：产品/页面类型、目标用户、首要任务、视觉风格、信息密度、视觉焦点、配色策略、动画强度、框架/现有 UI 库、约束、待确认问题。

用户对某一页面的选择不自动等于全站固定密度。比如美食首页可以低密度、大幅摄影，商品列表仍可保持可扫描性；复杂后台以操作效率为主，不强行叠加 Hero 或宣传文案。

## 阶段 4：视觉方案先于组件实施

敲定设计方向后，依次执行：

1. 明确构图和视觉层级：主体、比例、留白、信息顺序
2. 建立或复用语义 Design Tokens
3. 盘点组件并优先统一共享组件及所有状态
4. 使用共享组件组合业务页面
5. 按页面目标加入适度动效
6. 完成桌面/移动端、浅/深色、交互、键盘、可访问性与性能验收

不得为了展示更多信息而盲目塞满首屏；也不得为“高级感”制造无意义的空白或隐藏必需操作。

## 禁止行为与反面案例

- **无效问卷**：每次修改按钮也让用户重选整体风格。
- **自作主张**：未经确认就把推荐方案写成“用户选择”。
- **同质化模板**：所有网站都变成大标题 + 三张卡片 + 渐变背景。
- **密度僵化**：把用户的低密度首页偏好强制复制到数据表格。
- **平均视觉权重**：所有卡片、标题和图片一样显眼，缺乏焦点。
- **组件割裂**：为每页重写按钮、输入框、弹窗，不共享 Token 和状态。
- **动画炫技**：使用高负载特效阻碍阅读或操作。
- **虚假结果**：只完成静态视觉，却声称实现了业务功能。

## Agent 默认开场示例

“我先检查现有项目和内容，再给你 2–4 个适合该产品的风格方向，并说明信息密度和视觉焦点的区别。确定方案后先统一设计 Tokens 与共享组件，再开始业务页面。已有明确规范的部分会直接沿用。”

如果用户要求直接实施且提供了充分的约束，可以按已有信息继续，不得因冗长访谈阻塞工作。
