# RepoVantage 项目比较页截图审查（2026-11-04）

**证据来源：用户提供的完整 Safari 截图**，未检索 RepoVantage 业务代码，也未假设演示曲线真实。

## 截图观察

- 左边有仓库多选长面板（7 项列表、多项已选，下面时间和比较口径），右边有主要「开发活动对比」大折线图、下方「协作耗时对比」图、右侧「比较口径」内容稀疏的大面板、最后「综合对照表」。
- 选定 3 个仓库，而主线图视觉上仅一条明显折线；图例有多个项目，无法通过截图证明是缺数据、线重叠、被隐藏还是画错。**应检查选中 ID ↔ 数据系列 ↔ 图例 ↔ 表格列的一致性。**
- 内容大量采用连续卡片。左选择器吞噬持续横向空间，右侧“比较口径”卡留大块无信息面积；用户想比较仓库差别却要从多个区域自己拼答案。
- 数据表可见不同项目的样本与覆盖情况，可能存在部分/未完成数据；不能对不完整对象直接进行公平排名。
- 图例和表格字号偏小，截图下浏览成本大；不能仅通过增加容器间距解决。

## 建议的改造方向（保留真正业务约束）

1. 首屏首先显示对象 chips + 日期窗口与一句清楚的比较问题，不必让多选列表永久成为独立侧栏。
2. 紧凑差异摘要优先（但只有确实存在可比数据时产生）；共用度量的多仓库趋势用一张主图+清楚的系列图例。
3. 再放真正的列式比较矩阵；先展示高价值指标，次要指标可展开，复用同一时间窗口和单位。
4. 「比较口径」从宽大空卡改为与相关数据相邻的摘要说明/可展开详情（关键覆盖警告需常显）。
5. 多仓库复选要与实际图表/表格联动，不能选 3 个显示 1 条线而没有明确无数据解释。
6. 移动端 2 个对象的并排比较或对象切换，不能靠缩小文字让 3 列和全部长名称硬塞同一行。
7. 底部自然滚动到完整表格和导出操作，不能因为新增固定控件遮住最后记录。

**不能直接断言**：截图无法确认鼠标选择事件、工具提示、导出行为和真实数据加载错误。以上均是 Skill 设计策略与运行时测试清单，不代表 RepoVantage 已被修改或验收。
