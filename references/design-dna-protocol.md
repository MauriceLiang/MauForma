# Design DNA：参考网站的 WHAT / WHY / EVIDENCE

借鉴 Senlin Taste 的方法——不仅写“用了什么色”，还解释选择背后的权衡。MauForma 独立实现审查流程，不宣称能读取无法访问或未检验的远端网页。

## 输入与证据等级

- 可以访问的 URL：明确观察的页面、视口、日期；优先浏览器实际渲染。只拿到 HTML/CSS 时注明无法核对外部字体/图片/动画。
- 用户图片：仅解释像素层看得见的视觉特征；不要凭截图声称精确 CSS 数值或内部组件框架。
- 多页参考：比较不同页面的稳定共性；单页差异单独记录。
- 抓取内容不足：明确说明证据不充分，**不**凭空填真实颜色、动效技术栈、图像质量。

## 四步审查

1. **观察 WHAT**：界面主视觉主体，颜色层级、字体、留白、网格、圆角、阴影、图片比例、动效（只有实际观察过才可下结论）。
2. **提出 WHY**：例如“低饱和背景+高对比产品图”让食品成为唯一视觉焦点。标注它是“分析推断”而非作者公开陈述。
3. **评估替代**：若改成平均三栏卡片或等比缩图，会损失什么？若用户需要快速查表，原构图是否仍合适？
4. **可迁移约束**：提取可复用原则（内容焦点/层级/节奏）与不可移植的品牌专属元素（Logo、图片、独特插画）。

## 输出字段

`subject`、`reference_url`、`observed_pages`、`viewports`、`date`、`confidence`、
`design_map`（字体/颜色/间距/圆角/阴影/网格），`taste_decisions[]`：
`{trigger, decision, reason, evidence, rejected_alternative, inferred, suitable_sites, risk}`。

必须区分事实、推断和未知：样例文件 `examples/design-dna-record.json`。
遵守版权：不复制第三方独有照片、品牌资产、付费组件源代码；可参考合理的视觉规律。

## 适用判定

设计 DNA 是候选风格的补充证据；用户确认优先于“很像某参考网站”的推断。将采集结论映射到 MauForma 的八种风格档案，并按当前网站内容/用户目标给出匹配理由。
