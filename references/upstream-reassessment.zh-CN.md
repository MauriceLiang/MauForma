# 上游 Skill 再复盘与边界审计（中文）

> 2026-11-20 根据 README 列出的 14 个上游 Skill 重新核查了可访问的主规范，并对部分高价值参考文档做专项复核。本文不是上游 Skill 原文翻译，也不代表完整审核其所有源码、依赖或许可证。作者、链接和开源致谢统一见 [README](../README.zh-CN.md#设计-skill-与方法论启发)。详细英文对照及各项吸收程度见 [upstream-reassessment.en.md](upstream-reassessment.en.md)。

## 结论

MauForma 的方向不应是堆砌所有优秀 Skill 的指令，而应只吸收**适用场景明确、可观察、能验收、符合用户已确认设计权利**的方法。原中文专项规范虽然覆盖很多要点，英文入口迁移后仍有以下风险：旧文档的“必须”被理解为全部任务必做；“只有英文入口”被错误理解为英文产品 UI；“组件优先”被误解成无限制安装；合成动效被当成真实业务；不同 Figma MCP 权限混为一谈；静态设计漂移被当成品牌真实意图。

| 参考项目 | 值得吸收的具体能力 | 本次确认的迁移边界 |
| --- | --- | --- |
| **Stageshow** | 分镜、因果、静态封面可读性、逐帧演示复核 | 仅针对有意制作的演示/营销镜头；不能替代真正业务 E2E |
| **Anthropic Frontend Design** | 题材内容优先、明确视觉焦点、面向最终用户的文案 | 不把创意页面的强视觉默认复制到后台 |
| **Impeccable** | Audit/Refine/Polish 区分；Tool / Schema / Truth drift 三类维护 | 不自动安装 Agent Hooks；代码快照并非用户认可的 MASTER |
| **Senlin Taste** | WHAT、Pattern、WHY、Observer 与可验证的采集证据 | WHY 是有依据的推断，不能声称作者确认；不能越权抓取 |
| **Leon Taste** | 按真实业务构图、真实图片渲染与内容完整度检查 | 不套用“所有图片都不能有标题”等营销专属禁令 |
| **Anthropic Theme Factory** | 主题候选、预览、选择后再应用 | 演示主题不代表全站品牌授权 |
| **Designer Skills** | 简报、IA、可恢复任务、一个任务包含结构+样式+交互的纵向切片 | 小修复无需执行所有阶段，真实功能验收不能跳过 |
| **UI/UX Pro Max** | 意图检索、过滤错误领域结果、空结果重试、必要时 RTL | 不从无关样式库自动生成“已确认品牌” |
| **Vercel Web Interface Guidelines** | 精确 file:line、焦点/粘贴、表单错误与国际化格式 | 需要注明规范版本；不擅自联网或自称完成 WCAG 认证 |
| **Vercel Composition Patterns** | 显式组件变体与状态所有权 | React 19 API 要检查项目版本，不直接套入 Vue |
| **Vercel React Best Practices** | 优先检查请求瀑布与 Bundle，基于证据处理重渲染 | 不因微优化破坏语义或 SSR |
| **Vue Best Practices** | 单一状态来源、computed、props/events、生命周期清理 | Vue 专项按任务加载，不要求所有任务读取整套规范 |
| **Anthropic Webapp Testing** | 先看当前 DOM 再选 selector、记录 Console/Network、管理测试服务 | 没有浏览器就声明未测试；不能把 Mock 当真实保存 |
| **OpenAI Figma Implement Design** | 准确的 file/node、设计截图、资源和目标组件映射 | 桌面“当前选中”不等于远端可读；只有截图不能宣称 1:1 |

## 本轮实际修正范围

- **执行入口**：英文核心明确“主参考一份 + 有理由的辅助资料”；必要时可突破数量限制，不能因为表格某行包含多项就全部读取。
- **组件与权限**：优先现有可访问 UI 库；只有项目开发授权和依赖策略允许时才引入新依赖，禁止擅自改变全局 Agent 环境。
- **双语语义**：建立 15 组 B01–B15 契约，每条分别给出英文和中文的“触发/必需/例外/禁止”。中文见 [semantic-boundaries.zh-CN.md](semantic-boundaries.zh-CN.md)，英文见 [semantic-boundaries.en.md](semantic-boundaries.en.md)。
- **Figma/真实浏览器**：明确 MCP 输入能力、先观察真实 DOM、再做动作、记录失败与实际已验证范围。
- **国际化**：实际支持的语言和视口决定测试范围；支持多语言时检查日期/数字、真实中英文换行；不强迫纯桌面产品做手机或 RTL。
- **动效与设计漂移**：营销封面与业务操作分离；代码 Token、配置格式、产品设计事实三类不同，不自动重写 MASTER。
- **测试**：新增中英契约一致性、路由存在性及反例回归检查；CI 能证明静态文档未明显漂移，但不能证明任何大模型真的理解所有中文/英文语义。

## 不能过度承诺的事项

1. 本次没有逐行翻译全部历史中文参考库；英文入口加英文执行手册是国际用户可用的核心路径，但专项细节可能需要对照。
2. 上游 Skill 在不同版本、模型、工具宿主中的操作行为可能不同；引用并非自动安装、依赖或背书。
3. 文档和合成浏览器回归测试通过，**不代表真实用户 Web 项目视觉、后端、动效或者 Agent 完成率已验证**。语言效率需要在同一任务、同一模型和同一工具条件下运行对照实验。
4. 以后从外部新增参考时，必须写明来源、触发、适用范围、例外、不能做什么和证据，并同步修改中英契约与测试；禁止只追加一条笼统的“must”。

结论：**把优秀方法转为有触发条件、有真实证据、能跨语言核查的规则，比照搬所有 Skill 的强制命令更可靠。**
