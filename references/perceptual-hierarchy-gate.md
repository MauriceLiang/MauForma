# Perceptual Hierarchy Gate · 内容重要性先于字级

适用于所有 Web 页面（Operate / Persuade / Read / Experience）、所有框架及 UI 库。此处解决的不是“默认把字体调大”，而是**让用户当前要理解、判断或操作的信息获得足够的视觉权重**。所有尺寸范围是项目级选择，不是跨产品强制像素表。

## 1. 用用户任务建立优先级，而不是按 HTML 标签平均分配

在决定字号、字重、颜色、占用空间之前，先为真实界面填写一份轻量的 Information Salience Map：

| 层级 | 定义与判据 | 常见对象 | 处理方式 |
| --- | --- | --- | --- |
| P0 · 决策焦点 | 用户进入该视口要立即理解或操作什么？不看它会无法完成主要任务 | 当前项目/商品/文章、关键结果、阻断错误、主要 CTA | 明确的首要视觉焦点；位置、形状、字号和对比协同，不一定最大 |
| P1 · 完成任务必读 | 用户读完 P0 接着必须核对的关键信息 | 关键状态、价格与单位、任务行名称、重要变化、必要表单标签、下一操作 | 稳定的扫描节奏；通常正文级或更强，不得习惯性降为弱灰小字 |
| P2 · 支持理解 | 解释或帮助判断但不抢主任务 | 第二说明、时间、分类、普通详情、相关导航 | 较轻而可读；相邻信息紧密对应 |
| P3 · 低频上下文 | 非主要但可能为真实性、追溯或合规所必须 | 数据来源、脚注、更新时间、法律限制、辅助菜单 | 可以节制，但不可因层级低而不可读、不可到达或缺失 |

**重要：信息优先级不是数字检测器。**“7 个待处理”的数字若只是分页筛选附属值，可与标签共同行内阅读；当它是操作判断中心才放大。32 元商品价格、文章标题、错误解释或“保存”按钮可能比任意统计数字更重要。必要免责声明/风险不能被 P3 隐藏。P0 不等于最大标题：工作台常见的是对象/当前状态优先于页面 H1；品牌页面可由 Hero 主导。

## 2. 在页面排版前，写出可核对的三步

1. **写任务句**：用户在此页的第一句具体问题是什么？按当前状态区分初次/回访、正常/错误、桌面/手机。
2. **列真实信息**：每个可见文字/数字/按钮/状态对应 P0–P3、语义角色、被读到后用户能做什么；重复装饰文案先删，不用缩字体“塞进一屏”。
3. **预演阅读路径**：遮住品牌颜色和阴影，按“第一眼 → 第二眼 → 执行动作”读图。若首眼是无用大标题、空白容器或所有文字一样弱，回到信息顺序再设计。

使用最少的必要级差：**大多数任务区选择 2–3 个清楚的主要字级，必要时让 KPI、Hero 或报错独立成为更强的特殊角色**。不同视觉层级可由字重、位置、对比、间距、排版节奏形成；不只靠字号绝对差。默认主正文应可舒适阅读，11–12px 不得成为跨站主阅读级。复杂表格可提供可切换的密度，而不是固定缩小全部数据。

## 3. 项目级排版契约

- 针对项目生成 semantic typography tokens：display、page-heading、section-heading、primary-content、body、supporting、caption、control、critical-value（名称可按项目既有 tokens 调整），并有一个实际使用的映射表。使用项目字体、语言（CJK、英文、混排）、字体度量、内容长度和实际视口测量，不从一个截图硬推全站数值。
- 对每个 P0/P1 项检查：与相邻 P2/P3 的字重/对比/字级是否可一眼区分；标题或数值是否有**内容价值**而非只占大面积；长值和单位是否成组；文字本身是否可读。
- 不得通过“全部 18px”或“所有数字 28px”假装修复。对 200% 字体放大、窄屏、系统字体回退和长内容，用换行、响应式重排、显式折叠/层级而非无上限压小。
- 字号与密度要协商：先删重复信息、减少无效外层面板，最后再决定空间；不要为了“能在一屏放下”牺牲 P0/P1 文本。
- 对比度与放大验收遵照 WCAG 2.2 相关条款；规范不设统一法定最小 px，也不宣称自动视觉审计能证明符合 WCAG。图表 Canvas 内文字必须实际看渲染。

## 4. 四类页面同一判断法，不同视觉结果

| 模式 | P0 可能是谁 | 常见 AI 误区 | 更合适的审查点 |
| --- | --- | --- | --- |
| Operate 工作台/数据 | 当前对象、需要处理的状态/错误、主要列表项 | 所有文字 12–13px；无意义 H1 大、任务行反而弱；每个数字强行 KPI 大卡 | 任务身份、异常原因与可执行动作可扫描；P1 不被说明淹没 |
| Persuade 营销/商品 | 产品卖点、商品形象/名称、关键价格/CTA | Hero 很大但产品规格/价格/购买按钮极小；一切都做胶囊 | 艺术标题与信息转化路径兼容，关键条款不隐藏 |
| Read 文档/教育 | 文章主题、正文论证、例子与学习操作 | 目录比正文抢眼；正文小且行宽过长；代码/注释难读 | 长阅读舒适，标题—正文—注释关系稳定 |
| Experience 作品/互动 | 作品或当前叙事节点；必要的控制与出口 | 遮挡作品的控件墙或把控制文字缩到无法识别 | 主体验能被感知，导航和可达性仍成立 |

不要把 Operate 的小圆角、紧密表格或数值设计“推广”为所有类型的风格。用户已有视觉系统应继承；已有用户决策不可因泛化规则被自动覆盖。

## 5. Gate A / B / D 验收证据

**Gate A（设计前）**：明确当前页 P0/P1、最先读到的三个信息、角色 token 映射及最可能失败的长内容；不需要为每次按钮小修重新提交整页计划。

**Gate B（组件）**：按内容重要性映射到组件 slots/variants（例如 primary/secondary label、metric、empty/error、hint）；重点信息不能依赖某个页面临时 CSS 放大。组件跨长中文、英文、数字/单位、空态、loading、禁用和 200% 字体时均有边界策略。

**Gate D（真实截图）**：用 3 秒快扫测试，记录首眼读到什么、是否符合主任务；在灰阶下再次检查。分别查看桌面/窄窗、浅深主题、长内容与 200% 放大。若只做静态推断，标记 NOT VISUALLY VERIFIED；不要用“视觉层级分数 95”之类无依据分数代替证据。
