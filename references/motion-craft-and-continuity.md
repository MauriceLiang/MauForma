# Motion Craft & Continuity · 真实产品的高级动效语言

> 本规范借鉴 [Stageshow](https://github.com/benjitaylor/skills/tree/main/stageshow) 的「运动有原因、画面有叙事、过程需逐帧审查」方法，重新组织为跨 Vue/React/Svelte/Angular 等 Web 技术栈的实际交互规则。并非复刻其 React Kit、样例构图或专有 API。与 `motion-consent-experience-gate.md` 和 `component-motion-choreography-gate.md` 联合执行。

## Gate MC0 · 高品质动效是设计能力，不是特效数量

- 对需要交互的产品，在已获得的用户授权与当前项目 Motion Policy 内，**主动寻找能改善真实操作体验的状态连续性**，不要因为用户没有逐一指定 Tab、Dialog、筛选器动效，就降格成只做静态/路由 fade。没有授权时沿用原有选择门禁，推荐具体体验，不能把 Agent 偏好冒充用户授权。
- 动效的目的可分为 **确认操作**（press/feedback）、**建立位置关系**（共享指示器/布局重排）、**解释层级**（菜单从触发源展开）、**传递状态**（loading→result）、**构成叙事**（产品展示）。每个动作须归属其中至少一项；无意义装饰移除。
- 核心交互应该精致，但可以克制；高频操作比低频展示更要求快速、可反向、可中断。某个页面用动画少，不代表设计不高级；应解释哪些动作有连续性、哪些即时切换更好。
- 静态画面必须先成立：若排版层级、密度、留白和目标控件错误，动画不会补救。不要用持续漂浮、放射光、彩边或跟随鼠标的装饰遮盖基本问题。

## Gate MC1 · 从状态图到分镜，而不是先写 CSS

为高价值真实交互做最小 storyboard，不必为每次 hover 写长文：

`intent → trigger → before → during → after/payoff → interruption/reverse → reduced motion`

1. **Before**：操作对象、当前选中态、锚点与相关内容能直接辨认。
2. **Trigger**：鼠标/键盘/触屏/数据推送等真实原因；反馈从输入发生时立即开始。
3. **During**：标出谁移动、谁让位、谁淡出、谁延后；明确主次与因果顺序。
4. **After**：结果完整、可操作；不遗留半透明层、残影、空白占位、焦点丢失。
5. **Interrupt**：在 30% 或 70% 时再次触发或逆向，动画从当前可见位置衔接，不先跳回起点。
6. **Reduced**：取消不必要运动但保留状态、反馈、数据准确性和键盘可用性。

只有营销产品演示、教学流程或动画故事才需要 3–5 个较长的 narrative beats、收尾 payoff、poster 与可能的循环；**真实生产交互不能为了叙事让用户等待**。

## Gate MC2 · 连续性：同一对象不能「消失又重建」

- **Identity**：同一按钮从提交→处理中→成功应尽量复用其语义组件、DOM/框架 key 与焦点；切换文字/图标时，先留足最大内容宽度或让宽度与邻居同步变化。不得替换为形似但全新的按钮使光标/焦点瞬移。
- **Shared geometry**：选项卡指示器、导航选中背景、媒体图像、卡片详情可使用共享元素 / FLIP / layout 动画，使旧位置到新位置具有明确路径；确保元素在两态的对应关系唯一。
- **Neighbor response**：新行进入、列表删除、过滤/排序时，相关邻居应连续让位；不能新卡片先凭空出现，再在下一帧把其余行整体推开。高密度表格或大量实时数据可选择即时更新，保证正确性胜过视觉编排。
- **Entrance/exit**：真实需进出的内容应有匹配的入场和退场，退出期间保留可绘制节点直至结束；退出不阻塞 Escape、关闭、焦点恢复或业务响应。依赖原生 `display`、卸载与 Transition API 的实现应先核对当前浏览器支持。
- **Anchor**：Popover/Tooltip/Dropdown 以触发元素为稳定锚点；内容变化时避免「开着的菜单自己走位」。对话框、抽屉层级、遮罩、指针区域及滚动锁要同步。
- **Morph**：尺寸、位置、边界和内容共同协调。可以动画容器，但**不要缩放正文文字来假装重排**；优先约束宽度、交叉淡入、独立布局过渡，避免文字拉伸或模糊。
- **Handoff**：对象从一个容器迁移到另一个容器时，旧对象和新对象在交接瞬间应位置/尺寸匹配，不允许瞬移、重影、双重高亮。

## Gate MC3 · 时间节奏、缓动和层次

角色化设计，而不是每个元素套同一个 `transition: all 300ms ease`：

| 动效角色 | 建议运动方式 | 需要避免 |
| --- | --- | --- |
| 触控反馈 | 短促、按下即响应，pressed/focus 不等待 | 先延迟再显现确认 |
| 选择指示器 | 平滑位移与尺寸匹配、末端温和减速 | 原位置消失、新位置突然亮起 |
| 菜单/披露 | 由触发源建立空间关系、与内容呈现重叠 | 容器展开完成后才空白填文字 |
| 列表变更 | 新对象与邻居同步占位、位移衔接 | 一整列随刷新飞入 |
| 状态与数字 | 保持锚点、只改变真实变化部分、稳定宽度 | 数值捏造、无理由滚动、文字中间重叠 |
| 展示叙事 | 主体、支持元素错峰，明确 payoff 与停顿 | 所有元素同速同向反复移动 |

- 可借鉴 Stageshow 的**相关元素约 40–80ms 错峰**、不同曲线区分移动和进入、阶段重叠而不是一段完毕再来一段。**这些是产品演示启发式，不是整站通用硬阈值**。实际按钮反馈通常更短，输入和焦点应即时。
- 视觉上应看见：起动、行进、减速、稳定。设计时同时调整位移距离、持续时间和缓动；仅延长时长不能让突兀运动变自然。
- 有关联的变化共享时间线：点击→控件触感→主内容变化→次要标记补充；允许重叠但不得提前显示「成功」，也不得在业务已完成时人为延迟。
- 只在极少数核心识别性动效中使用弹性、超调或弧线；正文、表格、危险操作不应弹跳。Avoid global `will-change`、长期 running animations 和无意义循环。

## Gate MC4 · 字、数字、图表的运动仍是信息设计

- 字符和图标的实际像素比外框更容易暴露低质量：检查 transform 结束前后字体是否突然换层/变粗、基线是否跳、字被剪裁、笔画是否抖动。
- 标签变化前确定文字占位与对齐，长短内容切换时避免周围控件突然挪动。仅改变变化的词或数位；未知数据不能伪装成滚动计数。
- 图表插值须对真实对应数据、单位、时间窗、系列身份负责；首次加载与刷新不是同一个动效场景，频繁推送的图表不必每次完整重演。
- 加载→成功/失败的文本和可访问状态应及时同步；视觉动画只是辅助，不得让屏幕阅读器或业务提交等待。

## Gate MC5 · 指针、拖拽、滚动和展示叙事（按场景启用）

**真实应用**：遵守实际鼠标、触屏与键盘输入。拖拽从真实抓取点开始，拖动期间留有原位占位、目标位置反馈及取消回退；不能只让卡片漂浮而列表突然排列。滚动联动动画有停止、回退和减少动效策略，不绑架主滚动。

**仅用于营销/教学模拟演示**：可借鉴 Stageshow 的光标故事、输入/点击、按键提示、镜头裁切和场景构成；显式标注为 simulated demo，不得把假的点击/数据请求当作功能实测。光标移动必须有目标与因果；位置从真实元素几何测量，不写固定坐标假装适配。3–5 beat、10–16s 的循环是可选的展示叙事建议，非应用交互默认时长。开场和缩略图选择可单独表达价值的稳定帧；循环末尾的状态归位必须有明确因果或在不可见处重置，不能在可见区域突然倒放业务数据。

**构图只迁移原则**：主视觉焦点、层次、合适裁切与有意义留白，不能把 Stageshow 的小尺寸 demo、特定窗口框/手机 UI、占位文字和固定构图强制用于真实业务页面。

## Gate MC6 · 落地与保护

- 沿用项目原框架、UI 库、motion tokens。简单 CSS/框架 Transition；共享几何可用 FLIP、View Transitions API（检测支持并回退）、Motion 等；复杂序列按需选择 GSAP/Anime.js。不要把 Stageshow React Kit 直接移植到 Vue 或强制增加依赖。
- 动画的 key、portal、scroll lock、focus restoration、rAF、observer 和 timer 生命周期必须正确；卸载、隐藏 Tab、路由切换、快速重入时清理。以真实对象身份和可用性为先。
- 尊重 `prefers-reduced-motion` 的动态改变、用户明确的低动效/无动效选择；禁用不必要的移动和循环，保留业务与明确状态反馈。
- 避免大范围 layout thrash、全屏 blur、重滤镜与永久合成层；选择合适属性并在真实设备/视口测量。无测试证据不得声称 60fps、无 CLS 或零内存增长。
- 交互能在过渡中被取消、重复点击和切换；始终保持焦点指示、键盘路径与文字对比。

## 常见否决项

1. 只加全页 fade 就宣布完成全部组件动效。
2. 菜单、Tooltip、弹窗与触发对象空间关系不成立，或开/关时锚点漂移。
3. 相邻列表/内容突然跳位，删除/筛选操作没有合理连续性或有数据错误。
4. 按钮/文字/图标在同一状态切换中重影、卡顿、剪裁、替身替换或焦点丢失。
5. 过渡中再次操作跳回起点；后台/隐藏后继续无限运行、泄漏资源。
6. 一直动、循环打扰、所有卡片同样上浮、所有按钮同样弹跳；没有真实因果。
7. 减少动效时重要内容消失或结果不同；动效包装成假的成功/进度。
8. 只测静态截图或 Demo，不做目标页面真实操作前/中/后的动态复验。
